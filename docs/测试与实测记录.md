## 3. 实测发现的时延（决定架构的数字）

| 操作 | 实测 |
| --- | --- |
| `adb devices`（server 已起） | 15 ms |
| `fastboot devices` | 15 ms |
| `adb shell echo hi`（USB） | 45 ms |
| `adb shell echo hi`（无线） | ~180 ms |
| `adb shell getprop <单个>`（无线） | ~700 ms |
| `adb shell` 一次跑 10 个 getprop | ~3.6 s |
| `adb shell` 一次跑 getprop+wm+df+mem | ~3.9 s |

**结论**：无线 adb 的往返成本极高，任何"每条属性一次 shell"的写法都会把界面拖成十几秒。
设备信息因此改为**单次 shell 批量取**，从 ~11 s 降到 ~4 s，并且窗口改为异步加载。

## 4. 缺陷与修复记录

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `--list-commands` / `--out` 无输出 | `-mwindows` 进程没有 stdout | 先查 `GetStdHandle`，再 `AttachConsole` 兜底，直接 `WriteFile` |
| 2 | `--param "cmd=echo hi"` 丢空格 | 命令行引号在 `CreateProcess` 前被吃掉 | 调用方需自行加引号；脚本里用 `ProcessStartInfo.ArgumentList` |
| 3 | **`input.tap` 坐标可注入** | 坐标裸透传到设备侧 shell | 新增 `ParamKind::Coords`，构造期拒绝 `;` / `&&` / `$()` |
| 4 | 设备信息窗口卡死 UI 十几秒 | 14 次同步 adb 往返全在 UI 线程 | 合并为单次 shell + 异步加载 |
| 5 | 界面内部命令无法被脚本测试 | 只能在窗口里看 | 抽出 `reports.cpp`，GUI 与 CLI 共用 |
| 6 | `--open` 被 `--select` 顶掉 | 参数解析顺序 | `--open` 优先级最高，并同步选中树节点 |
| 7 | `--adb` 会把测试桩写进用户配置 | 直接 `SetAdbSpec + Save` | 改为 `SetTransientAdbOverride`，进程内有效 |
| 8 | 右侧面板控件被背景覆盖 | 主窗口缺 `WS_CLIPCHILDREN` | 加上后正常 |
| 9 | 深色预览块不生效 | 只读 EDIT 走 `WM_CTLCOLORSTATIC` | 在该分支里处理 `hPreview` |
| 10 | 危险徽标不显示 | owner-draw 的 STATIC 重绘不可靠 | 改为父窗口 `WM_PAINT` 自绘 |

## 5. 设备侧行为（不是 bug）

| 现象 | 说明 |
| --- | --- |
| `app.start` 输出一堆 `bash arg:` | `monkey` 往 stderr 打的调试信息，退出码正常 |
| `screenrecord` 报 `unable to configure video/avc at 1272x2772` | 编码器不支持该分辨率，自动回退 720×1280，录制成功 |
| `getprop ro.boot.slot_suffix` 为空 | 该 AOSP 镜像不是 A/B 分区 |
| `fastboot devices` 为空 | 设备处于 normal 模式，未进入 bootloader |
