## 2. 工程结构

```

  command_builder.{h,cpp}   BuildCommand：唯一产出 argv 的入口
  adb_runner.{h,cpp}    进程封装（Job object + 流式回传）
  parsers.{h,cpp}       adb 输出解析（纯函数）
  device.{h,cpp}        设备会话：当前设备、枚举、常用查询
  settings.{h,cpp}      config.json 读写 + 路径解析 + 工具探测

src/gui/           # AdbRT.exe
  main.cpp              入口与参数分派
  main_window.cpp       主窗口（布局、绘制、消息）
  theme.{h,cpp}         调色板与字体（集中管理）
  param_panel.cpp       参数面板（按命令动态生成控件）
  task.cpp              工作线程执行 + 流式回传
  dialogs.cpp           设置 / 确认 / Breaker 对话框
  builtin.cpp           文本窗口、设备列表、应用列表、文件浏览
  windows2.cpp          截屏、交互终端、实时日志
  reports.{h,cpp}       纯文本报告（GUI 与 CLI 共用）
  cli.cpp               --run / --list-commands
  install_cmd.cpp       --install / --uninstall（用户 PATH + 桌面快捷方式）
  selftest.cpp          --selftest（无窗口自检）
  stubs.cpp             内置命令分派表
  resources: app.rc.in / app.manifest / settings_dialog.rc / resource.h

src/tests/         # 无窗口测试
  core_tests.cpp        158 项单元测试（CTest 用例 core_tests）
  fake_adb.cpp          adb 桩（无设备也能端到端验证）

packaging/         # 打包与安装
  identity.json         版本号唯一真相源
  assets/               adbrt.svg（矢量母版）+ 生成的 png/ico
  scripts/install.ps1 / uninstall.ps1 / build-release.ps1

tools/             # 开发期脚本
  gen-icon.mjs          由同一份几何定义生成 SVG 与 PNG/ICO

.github/workflows/build.yml   手动触发的 build → package → release
```

规模：**约 5,700 行 C++**，无第三方依赖。

## 3. 命令表与 argv 构造

### 3.1 为什么用声明式命令表

所有 adb/fastboot 命令都是**数据**，不是代码：

```cpp
C(1101, "app.install", GroupId::App, kSelApk | kSelFile,
  /*needsDevice*/ true, /*needsFastboot*/ false, Danger::Careful,
  ParamKind::ApkFile, ParamSource::None, "apk",
  ExecKind::CliStream, kInstallFlags, 4, "install {flags} {apk}")
```

一份定义同时喂给：命令树、参数面板、命令行预览、CLI、未来的 AI 助手。
**改一条命令不需要动任何 UI 代码。**

### 3.2 字段含义

| 字段 | 作用 |
| --- | --- |
| `id` | 稳定整数 ID，只增不改（配置持久化、日志用） |
| `key` | `"app.install`" 形式的稳定字符串键 |
| `group` | 命令树分组（设备/应用/文件/屏幕/Shell/Fastboot/工具） |
| `applies` | 适用于哪种本地选择（文件/目录/背景/APK） |
| `needsDevice` | 需要一台在线 adb 设备 |
| `needsFastboot` | 走 fastboot.exe 而不是 adb.exe |
| `danger` | Safe / Careful / Destructive / **Breaker**（手打序列号才放行） |
| `param` / `param2` | 最多两个参数槽位（如 flash 的分区名 + 镜像文件） |
| `exec` | Internal（开窗口）/ Cli / CliPanel / CliStream |
| `flags` | 复选/单选/值型选项白名单 |
| `argvTemplate` | `"install {flags} {apk}"`，` ; ` 分隔多条命令 |

### 3.3 构造器（`BuildCommand`）的硬规则

1. **只产出 argv 数组，永不拼接 shell 字符串**；
2. 模板占位符 `{key}` 必须能在 `params` 里找到非空值，否则**构造失败**；
3. `{flags}` 只有在 `FlagSpec` 白名单内的 key 才会进 argv，值型按 `{v}` 替换；
4. `needsDevice` 的命令**自动在最前面插入** `-s <serial>`（adb 的全局选项必须在子命令前）；
5. 坐标类参数（`ParamKind::Coords`）在渲染前校验：只允许数字、负号与空格，
   段数必须是 2 或 5 —— 这是唯一会透传到设备侧 shell 的参数，必须在这里堵死注入。

```
adb -s 192.168.1.248:35713 install -r C:\build\app.apk
    ^^ 自动注入                        ^^ 白名单 flag
fastboot -s ABC flash boot_a C:\boot.img
```

## 4. 进程封装

```cpp
RunResult RunProcess(const std::wstring& exe,
                     const std::vector<std::wstring>& argv,
                     const RunOptions& opts);
```

| 特性 | 实现 |
| --- | --- |
| 不走 cmd.exe | `CreateProcessW` 直接执行，无 shell 注入面 |
| 取消是真的取消 | 子进程挂到 Job object，`TerminateJobObject` 连子进程树一起结束 |
| 流式输出 | 两条读线程分别泵 stdout / stderr，逐行回调 `LineSink` |
| 不卡 UI | 回调里只 `PostMessage`，真正的界面更新在主线程 |
| 超时 | `RunOptions::timeoutMs`，超时按取消处理 |

## 5. 输出解析

`parsers.cpp` 全是**纯函数**（无 IO、无全局状态），因此可以 100% 无设备单测：

| 函数 | 输入 | 输出 |
| --- | --- | --- |
| `ParseDevices` | `adb devices -l` | 设备列表（device/offline/unauthorized/recovery/sideload/bootloader） |
| `ParsePackageList` | `pm list packages` | 排序后的包名 |
| `ParseProgressPercent` | `push/pull` 进度行 | 0–100 或 -1 |
| `ExplainAdbError` | stderr | 中文解释（未命中返回空） |

## 6. GUI 架构

### 6.1 布局

```
┌ 顶栏（自绘）：图标 + AdbRT / Android 平台工具 ┬ 设备下拉 ┬ 刷新 ┬ Fastboot 专家 ┬ 设置 关于 ┐
├───────────────┬──────────────────────────────────────────────────────┤
│ 搜索框         │ 命令标题                          [危险级别徽标]      │
│               │ 参数（动态生成）                                      │
│ 命令树         │ 将执行的命令（深色代码块）            [复制]          │
│ （分组/危险标记）│ [执行] [取消]                                        │
│               │ 运行结果                          [保存] [清空]       │
└───────────────┴──────────────────────────────────────────────────────┘
  状态栏
```

### 6.2 关键实现点

| 主题 | 做法 | 踩过的坑 |
| --- | --- | --- |
| 视觉样式 | `app.manifest` 引入 comctl32 v6 | 没有清单 = Win95 灰控件 |
| DPI | `PerMonitorV2` + 按窗口 DPI 缩放所有尺寸 | —— |
| 不闪烁 | 窗口 `WS_CLIPCHILDREN` + 自绘 `WM_ERASEBKGND` | 缺 `WS_CLIPCHILDREN` 会把子控件盖掉 |
| 深色预览块 | 只读 EDIT 走 `WM_CTLCOLORSTATIC` 而不是 `WM_CTLCOLOREDIT` | 只处理 EDIT 会一直是白底 |
| 危险徽标 | 父窗口在 `WM_PAINT` 里画药丸 | owner-draw 的 STATIC 重绘不可靠 |
| 长查询 | 设备信息异步加载（先显示占位） | 同步会卡住消息循环 |
| 危险确认 | `Destructive` 二次确认；`Breaker` 需手打设备序列号 | —— |

### 6.3 线程模型

- **UI 线程**：只做界面，任何 adb 调用都在工作线程；
- **工作线程**：`StartRun` 起一个线程，逐条执行 argv，通过 `WM_APP_TASK_LINE` /
  `WM_APP_TASK_DONE` / `WM_APP_TASK_PROGRESS` 回主线程；
- **取消**：`g_app.cancelFlag`（`std::atomic<bool>`）由 Job object 终止落地。

## 7. 配置与路径解析

### 7.1 config.json

```jsonc
{
  "adb.path": ".\\platform-tools\\adb.exe",
  "fastboot.path": "%LOCALAPPDATA%\\Android\\Sdk\\platform-tools\\fastboot.exe",
  "device.current": "192.168.1.248:35713",
  "expert.fastboot": false,
  "ui.defaultRemoteDir": "/sdcard/Download",
  "ui.captureDir": ""
}
```

扁平键值表，未知键原样保留；写入走 `.tmp` + `MoveFileEx` 原子替换。

### 7.2 路径四种写法

| 写法 | 例 | 解析 |
| --- | --- | --- |
| 绝对 | `A:\platform-tools\adb.exe` | 原样 |
| 相对 | `.\platform-tools\adb.exe` | 相对 **exe 所在目录** |
| 环境变量 | `%LOCALAPPDATA%\...` | 先展开再解析 |
| 波浪号 | `~\platform-tools\adb.exe` | 等价于 `.\` |

自动探测顺序（配置为空时）：
`<exe>\platform-tools` → `<exe>` → 用户 PATH → `%ANDROID_HOME%` →
`%ANDROID_SDK_ROOT%` → `%LOCALAPPDATA%\Android\Sdk\platform-tools` → 系统 PATH。

## 8. 安装与卸载

### 8.1 只做两件事

| 动作 | 实现 | 说明 |
| --- | --- | --- |
| 用户 PATH | `HKCU\Environment\Path`（`REG_EXPAND_SZ`） | **唯一**改动的系统状态；幂等，卸载时移除 |
| 桌面快捷方式 | `IShellLink` + `IPersistFile` | 指向安装目录的 AdbRT.exe |

**不创建、不修改、不删除任何注册表项**（`HKCU\Software` 下没有 AdbRT）。

### 8.2 脚本分工

```
install.ps1                     铺文件 + 调用 AdbRT.exe --install
  └─ AdbRT.exe --install <dir>  [--no-path] [--no-desktop] [--quiet]
uninstall.ps1                   调用 AdbRT.exe --uninstall，随后自删目录
```

`install.ps1` 支持 `-InstallDir`（相对或绝对）、`-NoPath`、`-NoDesktop`、`-DryRun`；
不指定 `-InstallDir` 时默认装到**脚本所在盘的根目录 `\adbRT`**。

## 9. CLI 门面

```powershell
AdbRT.exe --list-commands [--out 文件]
AdbRT.exe --run <key> [--param k=v]... [--flag k=1]... [--serial X] [--dry-run] [--out 文件]
```

设计要点：

- `--run` **仍然经过 `BuildCommand`**，不存在绕过白名单的旁路；
- `--dry-run` 只打印即将执行的 argv；
- 界面内部命令（`device.info` / `app.list` / `tool.doctor`）用 `reports.cpp` 输出文本，
  所以只读信息类也能被脚本全量验证；
- GUI 子系统（`-mwindows`）没有 stdout：`cli.cpp` 先看 `GetStdHandle`，
  失败再 `AttachConsole`，最后直接 `WriteFile`。

## 10. 构建系统

```powershell
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_CXX_COMPILER=A:/msys64/ucrt64/bin/g++.exe `
  -DCMAKE_RC_COMPILER=A:/msys64/ucrt64/bin/windres.exe
cmake --build build/release
```

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| `ADB_WERROR` | OFF | 告警当错误（CI 打开当门禁） |
| `ADB_BUILD_GUI` | ON | 构建 AdbRT.exe |
| `ADB_BUILD_TESTS` | ON | 构建 CoreTests 并注册进 CTest |

- 版本号唯一来源：`packaging/identity.json`（`cmake/identity.cmake` 派生 `version.h`）；
- 可复现构建：设 `SOURCE_DATE_EPOCH` 后固定 PE 时间戳 + `-ffile-prefix-map` 抹掉绝对路径；
- MinGW 细节：`wWinMain` 需要 `-municode`；`.rc` 的 `FONT` 行必须写全四个参数，否则 windres 报语法错误。

## 12. 已知限制与后续

| 项 | 现状 | 计划 |
| --- | --- | --- |
| 设备信息耗时 | 无线 adb 单次往返 ~700ms，已合并成一次 shell（~4s） | 可缓存到配置，或走 `dumpsys` 单次导出 |
| `app.start` 日志噪音 | `monkey` 会往 stderr 输出 `bash arg:` 调试行 | 过滤 stderr 里的 `bash arg:` 前缀 |
| `screenrecord` 首帧报错 | 1272×2772 编码器不支持，自动回退 720×1280 | 面板默认按 720p 预设 |
| 参数面板不滚动 | 参数特别多的命令靠固定高度 | 参数宿主加 `WS_VSCROLL` |
| 自绘按钮 | 目前是系统按钮（已是现代样式） | 需要跟随主题色时再做 owner-draw |
| 深色主题 | 调色板已集中 | 加一份暗色调色板 + 跟随 `WM_SETTINGCHANGE` |
| AI 助手 | 命令表已就绪 | 自然语言 → 命令 key + 参数 → 白名单校验 |
