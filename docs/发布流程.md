# 发布流程

> 目标：**只有全部构建成功才会建 tag**，且 tag 号由人手动输入。
> 这条流水线一次都不会被 push / PR 自动触发。

## 1. 手动跑一次

1. 打开 GitHub → Actions → 左侧选 **build** → 右侧 **Run workflow**
2. 在 `tag` 输入框里填版本号（形如 `v0.1.0`）
   - **填了** = 构建 + 打包 + 建 tag + 发 Release
   - **留空** = 只构建 + 打包，不碰 tag、不发 Release
3. 点 **Run workflow**

## 2. 流水线结构

```
build (Debug)   ─┐
build (Release) ─┴─→ package ─→ release
                                 ^ 只有 needs.build.result == 'success'
                                   && needs.package.result == 'success'
                                   && tag 非空 才进入
```

| 环节 | 做什么 | 不做什么 |
| --- | --- | --- |
| `build`（矩阵 Debug + Release） | MSYS2 UCRT64 工具链 → cmake 配置（`-DADB_WERROR=ON`）→ 构建 → 上传二进制 | 不做任何额外验证步骤 |
| `package` | 取回 Release 产物 → 归位 → 组装 zip → 上传 | **不重装工具链、不重新编译** |
| `release` | 取回 zip → `git tag -f` + 强推 → 建/覆盖 GitHub Release | 构建失败时根本不会进入 |

## 3. 关键约束

```yaml
on:
  workflow_dispatch:            # 唯一触发方式
    inputs:
      tag:
        description: "发布 tag（形如 v0.1.0，留空则只构建不发布）"
        required: false
```

- **不会**因为 push 或 PR 自动运行；
- `release` 的 `if` 显式校验 `needs.*.result == 'success'`，
  即使上游 job 被 skip 也不会误建 tag；
- 同名 tag 一律走 `git tag -f` + `git push --force` 覆盖，Release 用 `softprops/action-gh-release` 覆盖；
- 步骤里**不加验证步骤**（自检、ctest 这些不放进 workflow，本地跑）。

## 4. 版本号

唯一真相源是 `packaging/identity.json`：

```json
{ "version": "0.1.0.0" }
```

它派生出：

- `version.h` 里的 `ADB_VERSION_STR` / `ADB_VERSION_COMMA`
- exe 的 `FileVersion` / `ProductVersion`
- 发布包名 `AdbRT-0.1.0.0-win-x64.zip`

**没有明确要求不递增版本号。** 如果只是修 bug，直接重跑 workflow 用同一个 tag 覆盖即可。

## 5. 产物

```
AdbRT-<版本>-win-x64.zip
├─ app\
│   ├─ AdbRT.exe
│   ├─ adbrt.ico / adbrt.png / adbrt.svg
├─ install.ps1
├─ uninstall.ps1
├─ 使用说明.txt
├─ README.md
└─ LICENSE
```

用户在解压目录里执行：

```powershell
pwsh -File install.ps1                                    # 装到当前目录
pwsh -File install.ps1 -InstallDir D:\tools\AdbRT        # 指定位置（相对或绝对）
pwsh -File install.ps1 -NoPath                            # 不改用户 PATH
```

## 6. 本地复现 CI 的构建

```powershell
$env:Path = "A:\msys64\ucrt64\bin;" + $env:Path
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release `
  -DADB_WERROR=ON `
  -DCMAKE_CXX_COMPILER=A:/msys64/ucrt64/bin/g++.exe `
  -DCMAKE_RC_COMPILER=A:/msys64/ucrt64/bin/windres.exe
cmake --build build/release
```

CI 与本地唯一的差别是编译器路径（CI 用 `C:/msys64`），以及 ccache 缓存。

## 7. 排错

| 现象 | 检查 |
| --- | --- |
| `release` 没有出现 | tag 是否留空了；build/package 是否有 `cancelled` 或 `failure` |
| 打包 job 找不到 `AdbRT.exe` | `download-artifact` 的落地层级是否与 `build-release.ps1` 期望的 `build/release/src/gui` 一致 |
| 本地能编、CI 编不过 | 99% 是 `-DADB_WERROR=ON` 把本地忽略的告警变成了错误 |
| 产物里出现绝对构建路径 | 没设 `SOURCE_DATE_EPOCH`，或 `-ffile-prefix-map` 被覆盖 |
